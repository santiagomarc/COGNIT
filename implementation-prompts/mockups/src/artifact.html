01 · What is actually wrong

A three-step ladder, one step spent

The brief says the app reads “flat and static” and that almost everything is black, grey and white. Both halves of that sentence are true, but only the first one is a defect. The palette is doing its job. The problem is that every container on every screen is the same plane.

The system defines three surface steps — --bg #09090b, --surface #131316, --surface-raised #1f1f23 — and one elevation, --elevate-flat, an inset white highlight at 5 % opacity. On the deck page, six .surface blocks and roughly ten major components all sit at that same step, with that same elevation, at near-equal visual weight. Nothing is primary because nothing is anywhere.

That is not a colour problem, and it will not be fixed by adding one. It is fixed by spending the ladder: putting the primary object above the surface, the subordinate content below it, and letting light fall across the ground behind both.

The operative rule from the brief, restated

Banned: chromatic decorative blobs, coloured glow, neon shadow, any hue that does not encode spaced-repetition state. Permitted: monochromatic ambient lighting — low-opacity white/zinc radial fields, fine grain, vignettes, specular hairlines — used to create planes and depth. Depth in this system comes from light and elevation, never from colour. Every device below obeys that.

02 · Research

What mature dark products actually do

Named techniques, not vibes. Each one is here because it solves a specific part of the flatness problem without touching hue.

SourceTechniqueWhere it lands here
LinearElevation is a luminance step on the surface background (white opacity 0.02 → 0.04 → 0.05), not a shadow. The plane boundary is a 1px solid rgba(255,255,255,0.05–0.08) border. Validates the existing ladder and says to use all of it. Cognit's steps are already correct; they were simply never assigned by role.
LinearThe recessed plane: box-shadow: rgba(0,0,0,0.2) 0 0 12px 0 inset for sunken panels. The one step Cognit does not have. Becomes .well — the deck index and the card list. This single addition is what lets three containers read at three weights.
RaycastDark-on-dark bands separated by hairline dividers, never alternating light/dark sections. Surface ladder #07080a → #0d0d0d → #101111, 6–10px radii. The dashboard's four bands. No band changes brightness to mark itself; the rule and the plane do it.
Vercel GeistA repeating texture at 5–10 % opacity on a 16/24px grid; “every divider, border and disabled state lives on its own deliberate step.” The static grain tile, and the discipline of picking --border vs --border-strong vs --border-control by role rather than by taste.
Your own LandingBackground.tsxThe “specular horizon hairline” — a 1px rule painted with a radial gradient so it fades to nothing at both ends. Promoted from decoration to structure. Every section rule and column divider in these mockups is gradient-masked. It is the cheapest single fix for “everything looks like a box”.

One computed finding you should know about

Rather than eyeball the state channel, I ran it through the dataviz palette validator. The result is worth recording, because it makes an existing rule load-bearing:

LIGHT  --state-learning #a16207  ↔  --state-due #c2410c
       ΔE 0.6 (deuteranopia)  ·  ΔE 8.8 (normal vision)

DARK   --state-learning #facc15  ↔  --state-due #fb923c     ΔE 14.6 (normal vision)
       --state-mastered #4ade80  ↔  --state-learning #facc15  ΔE 6.8 (protanopia)

In light mode, due and learning are effectively the same colour to a deuteranope, and they are already hard to separate with full colour vision. I am not proposing a change — §5 puts the state channel out of scope, and each value is a deliberate semantic choice. But it means §2.3's “colour is never the only carrier of meaning” is not a belt-and-braces nicety; it is the only thing keeping the state channel legible. Every swatch in these mockups carries a word or a number beside it, and any future “just show the ticks” shortcut is a real accessibility regression.

Ambient field

Two or three large radial-gradient stops on one pointer-events:none layer. Static — the landing page's breathing halos with the animation removed.

Static grain

The same SVG fractal-noise data URI, 180px tile, 3.2 % dark / 2.0 % light, plain opacity — no mix-blend-mode, which would force a compositing pass.

Gradient hairline

linear-gradient(90deg, transparent, var(--border-strong), transparent). Section rules and column dividers stop reading as box edges.

Specular top edge

A masked 1px highlight that fades at the corners, so a 1300px panel does not read as a drawn rectangle. Deliberately off in light mode, where a white edge on a white card has no job.

Performance — the §3 constraint

LandingBackground runs ~5,500 distance checks per frame plus three canvas ribbons. None of that appears here. All four devices above are background-image paints on one element per screen: zero per-frame work, no canvas, no requestAnimationFrame, no cursor tracking. Nothing animates, so there is nothing for prefers-reduced-motion to disable — which is a stronger guarantee than respecting it.

What changed and why

The left half stops describing the product and starts being it. A tagline plus three sample rows is a marketing panel; every SaaS login has one. In its place: the card, bracket-framed on the flat ground exactly as the study canvas renders it, and beneath it the grade deck, inert, showing four real SM-2 intervals. The three specimen rows — the one genuinely good element on the old page — move from footnote to the base of that column.

This is the one real risk in the set. It is justified: the grade deck is the product's signature object and the single place the flat system yields to tactility. Nobody else's sign-in page has one, because nobody else's product does. It also does something a tagline cannot — it tells a returning user what the session waiting for them looks like.

The hard border-r becomes a gradient hairline that fades at top and bottom. That single change is most of why the page no longer reads as two rectangles pasted together.

The heading steps down from 48px to 36px. In a 420px panel, --type-display-lg was competing with the wordmark rather than sitting under it. 36px is still on the scale and still well above the 24px serif floor.

What I did not change: the 55/45 split (it earns its keep once the left half carries information), the contained .panel at --elevate-2, the control geometry from Fix Pack 1, the OAuth row, or any copy in the form itself.

The five requirements

#RequirementHow it is met
1Heatmap and activity visible at first paint, 1440×900, no scrolling The signal band sits third of four, at ~460px. Six months of activity, retention and streak are all above the fold — and so are nine deck rows, against the Rev. B acceptance bar of six.
2Create Deck becomes its own prominent container A full-height 340px panel beside the due band, with a bracket-framed +, a 16px/600 title, a description and ⌘N. Prominence comes from container mass and position, not fill — see the trade-off below.
3Import PDF removed from this page entirely Gone. “Generate cards from a PDF” survives only as a way to create a deck, inside the Create Deck panel — which is a different action from importing into an existing deck.
4Telemetry cluster moves right Top row, right-aligned, baseline-aligned to the greeting, with the ⌘K affordance at the end. Unchanged Telemetry component.
5Greeting header on the left Good evening, Marc in Instrument Serif at 36px, with a dated sub-line that carries real information rather than filler: 9 of 12 decks need you today.

Structural changes beyond the five

  • The right rail is gone; the page is four full-width bands. A 320px rail cost the deck table a fifth of its width, and with names like Data Structures & Algorithms that width is not spare. Retention and streak lose nothing by sitting in a divided panel instead of stacked cards.
  • Retention, streak and the heatmap are one container split by two gradient rules, not three cards. Three cards read as three unrelated things; one divided instrument panel reads as one reading of the same subject, which is what they are.
  • The 7-day forecast moves inside the due band. It is the same measure as the hero figure, one step into the future, and the pairing makes both more readable than either alone. It also removed a section and the dead space in the band at the same time.
  • The forecast starts tomorrow, not today. This one came straight out of using your real numbers. At 519 due, today's column is 4.6× the tallest projected day and flattens the other six to stubs — the chart becomes unreadable at exactly the data volume you have. Today's count is already the hero figure two inches away, so plotting it twice bought nothing and cost the chart.
  • The deck index sits in the recessed plane and is clipped by the viewport bottom, which is how a list says “there is more” without a control.
  • Default sort becomes Most due. With 519 due across 9 decks, newest-first answers a question nobody is asking.

Trade-off you should weigh

Requirement 2 asks for Create Deck to be “visibly a priority feature”. §7.2 allows at most one filled button per screen, and the dashboard's is Start session. I resolved it with mass rather than fill: Create Deck is the second-largest object on the screen and sits at the top right of the primary row, but stays unfilled. If you would rather it were filled, that is a deliberate exception to §7.2 and worth writing down as one — not something to let drift in.

06 · Surface three

Deck page

“Too messy… so many numbers, so many card containers.” You are right that all of it matters, so nothing here is deleted. Two defensible structures, both built.

Option A · recommended

Workspace — a persistent header and four segments

Identity, telemetry and the mastery bar stay pinned at the top on every segment. Below them: Overview · Cards · Insights · Chat. Ingestion demotes from three stacked surfaces to two buttons in the segment bar.

Why this one. “Overwhelming” is a statement about quantity on screen, and segmentation is the only device here that actually reduces it. Ten components at equal weight become four zones at three elevations. The Overview segment keeps a window onto every other segment — a card preview, the weakest concept, the scheduler split — so the tabs organise rather than hide.

The three planeswhat carries the hierarchy
  • Raised — the review launcher. One object, one filled button, the deck's due count as the hero figure. This is what the page is for.
  • Surface — the readings panel: scheduler state as a labelled stacked bar, mastery trend, weakest concepts. Divided by a gradient rule, not split into cards.

Option B · alternative

Console — one scroll, three planes, a quiet rail

No tabs. The main column runs raised launcher → a single collapsed Add content bar → the card well. Retrospective readings — weakest concepts, top concepts, quiz history — move to a 318px rail where they are present but subordinate.

When to prefer it. It hides nothing, it is the smaller build (no segment state, no routing), and it shows all three planes at once, so it answers “flat” slightly harder than A does. The cost is that it is still a long page: it fixes the weight problem without reducing the count.

What both options do

  • Six same-weight .surface blocks become three planes. This is the whole fix. Nothing was deleted — AddCardForm, PDFUploadZone, BulkImportModal and DeckChatWidget all still exist, behind one Add content affordance instead of three stacked containers competing with the card list.
  • The deck's due count becomes a hero figure. 334 in --state-due at 42–44px mono, next to the one filled button. The old page had a telemetry strip where every reading was the same 13px, so the one actionable number was buried among five descriptive ones.
  • Scheduler state gets a form, not a list. A single stacked bar with 2px surface gaps, every segment labelled with its count. Zero-value segments do not render at all.
  • Top concepts stops being a full-width section. It is a tag list; it never needed a band of its own.

The greeting name — do not reintroduce F-06

There is no profiles table in supabase/migrations/, and user_metadata is referenced nowhere in src/ today. So the chain is:

  • user.user_metadata.full_name — populated by the Google and GitHub OAuth providers.
  • user.user_metadata.name — the GitHub fallback.
  • The email local-part, title-cased and stripped of separators (santiagomarcstephen → Santiago), never the address itself.
  • No name at all → Good evening, with no name. The greeting must read correctly with the name removed, which is why the sub-line carries the information and the greeting carries none.

Email/password signups have no full_name, so the local-part branch is the common path today, not the edge case. Worth building a real profile field if the greeting is going to be permanent.

Structural, not cosmetic

  • Option A needs segment state. Make it a URL param (?tab=cards) rather than useState — the deck page is deep-linked from the dashboard, the due band and share links, and a tab that resets on back-navigation will be reported as a bug.
  • The deck page's data loading changes shape. Today it fetches cards, mastery, topics and quiz-ready counts in one server pass for a single scroll. Under A, only Overview needs all of it at first paint; Cards and Insights can stream behind Suspense as they already partly do.
  • The dashboard's fold budget is now load-bearing. Requirement 1 holds at 1440×900 with the band heights in these mockups. Anything added to bands A–C pushes the heatmap down. Worth a comment in the page file saying so.

08 · Findings

Drift found while reading the repo

Not part of the design proposal. Flagged because §7 asked me to verify the current state and report what did not match.

FindingWhereDetail
Serif is being faux-boldedWordmark.tsx, LoginClient.tsx, [deckId]/page.tsx, globals.css .flip__body All apply font-medium / font-weight:500 to Instrument Serif, which ships at 400 only. The browser synthesises the weight. This is the “No Bold Serif Rule” in §3.2 — the mockups here use 400 throughout.
Type tokens are staleglobals.css vs COGNIT_DESIGN_SYSTEM.md §3.3 The CSS still holds the Rev. B corrections values (--type-display-lg: 2.75rem); the spec was later updated to the 1.5× scale (3rem, plus a new --type-display-xl: 4.125rem). Components hardcode text-[3rem] and text-[66px], i.e. they follow the spec and bypass the tokens. Three sources, two of them disagreeing.
Section order differs from the brief[deckId]/page.tsx §4.3 describes the 143-line lg:grid-cols-2 block as content ingestion followed by a study/quiz row. It is the reverse: the grid is the study/quiz pair (lines 436–578), and ingestion follows it. The diagnosis is unaffected.
Landing vignette is hardcoded blackLandingBackground.tsx line 436 rgba(0,0,0,0.45) is applied in both themes, so light mode gets a heavy dark vignette on a #fbfbfc ground. Every other layer in that file is correctly themed via --blob.
Unstyled anchors inherit indigogeneral Hit this while building: an <a> with text-decoration:none but no color renders in the UA's default indigo — the exact hue the system bans. A global a { color: inherit } makes it impossible to reintroduce by omission.

Live HTML and CSS at native resolution — every frame above is the real rendering, not an image. Built on the approved Rev. B chassis: neutral obsidian palette, the SM-2 state channel as the only hue, Geist Mono with tabular-nums for data, Instrument Serif at 400 for display type ≥24px. No sparkles, no glow, no orbs, no backdrop-blur outside a modal scrim, no indigo.
